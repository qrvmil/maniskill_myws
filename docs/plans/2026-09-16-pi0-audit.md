## Pre-outcome clarification: LoRA initialization

Inspection of pinned `models/lora.py` before any D0 baseline/SFT run found that
both LoRA factors use normal(stddev=.01), so the zero-update train state is not
identical to the official dense pretrained function. Preserve this exact V4
initialization. Primary zero-update baseline loads official dense pi0 weights
with D0 transforms/statistics. Additionally evaluate the saved LoRA initial
state as `lora_initialization`, N50/task on the same seeds. This auxiliary
comparison isolates initialization effects from gradient updates; it is not
a different training run or a model-selection opportunity.
